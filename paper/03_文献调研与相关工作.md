# A. background 四篇论文：v3 中的角色

| 论文 | v1 中的角色 | v3 中的角色 | 具体用法 |
|---|---|---|---|
| BLANKSKIP | 创新点 1 的原型 | **被切割对象** + v1 废弃证据 | 论证"内容自适应省算力"已被占；本文方向相反（契约 ⇒ 负载可预测） |
| EvoComp | 门控损失增强 | **不相关**（MLLM token 压缩） | 2.4 节一句并列，说明该思想在多模态上已被占 |

| NuWa | 创新点 2（免重训剪枝） | **可选工程手段** | 若某层量化回退过大，用其通道对齐 + 闭式重建获得量化友好结构，**不作为贡献** |

一句话：**v3 的创新在判决层的算术，四篇 background 论文都不在贡献清单上。**

## A1. BLANKSKIP: Early-exit Object Detection onboard Nano-drones (arXiv 2603.28149)

- **做了什么**：Crazyflie 2.1 + GAP8（<10 MiB、~1 W）上，用极轻辅助分类器判断"本帧是否无目标"，blank 帧跳过 SSD 主干；吞吐 +24%，mAP −0.015。
- **v3 的切割**：本文**不改算力分配**，恰恰相反——"误警率恒定 ⇒ 候选数恒定 ⇒ 负载与尾时延可预测"。BLANKSKIP 是"先预测难度再省算力"，本文是"先钉住契约，负载自然收敛"，因果方向相反。
- **另一种相关**：它同样在 MCU 级定点设备上部署，可作为"定点部署已有先例"的旁证，但**没有一篇报告量化后的 P_fa**。

## A2. EvoComp: Visual Token Compression for MLLMs (arXiv 2604.17087)

- **做了什么**：encoder-only 轻量压缩器选 token，进化搜索生成监督标签，损失 = GHM + 语义分离正则；3× 压缩保 99.3% 精度。
- **v3 关系**：任务域无关。仅在 2.4 节"内容自适应计算"作一句并列引用。

## A3. Fast-FoundationStereo: Real-Time Zero-Shot Stereo Matching (NVIDIA)

- **做了什么**：蒸馏压缩混合骨干 + 分块 NAS（时延预算下搜代价聚合）+ 结构化剪枝 + 1.4 M 野外伪标签；快 10×+，zero-shot 几乎持平。
- **v3 借什么**：只借评测纪律——"约束写在真实时延上而不是 FLOPs 上"、"轻量化必须与基础模型同口径对比"。
- **不借什么**：不做 NAS、不做蒸馏主导方案。

## A4. NuWa: Class-Specific Lightweight ViTs for Edge Devices

- **做了什么**：两阶段免重训——①冻结权重只训二值掩码（TopKBinarizer 直通梯度），类特定用 head_focus；②闭式重建（MHA 用 SVD 能量回注，MLP 用 `G=(2XᵀX+γI)⁻¹` 或 `pinv` 最小二乘）。类特定任务超 SOTA 免训练剪枝最高 29%，快 33.69×。
- **v3 关系**：**可选工程手段**。若 AMCT 在某些层回退过大，可借其"通道 8/16 对齐 + 最小二乘重建"得到量化友好的权重分布，但只在"实现细节"一句出现。
- **学术诚实点**：v1 把它当创新点 2 是移植，这是被否的核心原因之一。

## B3. 量化后训练（PTQ）/ 量化感知训练（QAT）—— v3 的新主战场之一

> 这是本文最直接的邻居，也是最容易被审稿人拿来质疑"你只是工程"的地方。必须逐条切割。

- **PTQ for detection 的现状**：研究几乎全部以 **mAP / AP** 为目标。
  - **Inlier-Centric PTQ for Object Detection（ICLR 2026）**：指出检测任务的量化误差主要由"inlier（与目标特征相似）的困难背景"驱动，据此设计校准与重构策略，以恢复 mAP。
  - **Vitis AI 精度验证方法论**：官方流程要求 INT8 与浮点基线的 mAP 差 ≤1%，否则回去改校准集——**整个生态的验收口径就是 mAP**。
  - **QAT 家族**：以重训与标注为代价换 mAP，本文不采用（本文的部署侧只做 PTQ + 标定）。
- **本文的切割（核心一句）**：他们把量化误差当**均值意义上的精度损失**去最小化；本文把量化误差当**尾部量纲上的统计漂移**去界住。二者目标函数不同：mAP 是对全排序的积分，`P_fa = 1e-3` 是 99.9% 分位——**尾部误差在 mAP 上几乎不可见**。
- **由此产生本文的存在性图**：同一模型、同一 `.om`，mAP 差 <1 点而 P_fa 差数倍。若这张图成立，B3 整条脉络就是本文的动机，而不是威胁。

## B4. INT8 的可移植性 —— v3 的新主战场之二

- **Is INT8 Portable?（arXiv 2609.16085）**：实测 FP32 在 1000/1000 用例上逐 bit 一致；INT8 若共享同一整数 kernel 也 1000/1000；但**跨 kernel / 跨平台只有 958–965/1000 一致**。
- **它说明了什么**：INT8 的不可移植是**事实**，不是工程瑕疵。因此"在 FP32 下标定阈值、在 INT8 上推理"在原理上就不成立。
- **它没做什么**：只**测量不一致**，没有给出（i）不一致对下游统计量（尤其尾分位数）的**解析界**；（ii）在整数域内**恢复契约**的判决规则；（iii）**免数据**把阈值搬到新配置的规则。
- **本文的切割**：把"不一致"从"报告一个百分比"变成"**可预测、可界住、可搬运的量**"。这三点正是 C1 的内容。

## B5. 恒定误警率检测（CFAR 传统 → 学习型 CFAR）

- **经典 CFAR 家族**：CA/OS/GO/SO-CFAR，杂波分布建模（K 分布、G⁰、Weibull），SAR 图像 2D CFAR。
- **为什么经典 CFAR 没解决本文的问题**：它建模**像素幅度分布**，不是**深度检测器的响应分布**；判别力弱，近岸/多目标场景 CFAR 窗被污染，"恒定"失效。更重要的是：**它工作在浮点或定点 DSP 上，从不讨论"量化后的 CFAR 是否还是 CFAR"**。
- **CFARnet（arXiv 2208.02474）**：把 CFAR 思想搬进学习检测器——损失中**软惩罚**零假设下分数分布的不一致；任务是 1D/2D 雷达信号单元级判别，无检测框、无边缘部署、无有限样本保证。
- **本文的位置**：**不是回到 CFAR，也不是在损失里"鼓励" CFAR**，而是把判决阈值变成一个**在整数算术上成立的可证统计量**。

## B6. 不确定性与 conformal prediction

- **SeqCRC（arXiv 2505.24038）** 等：用**带标签校准集**给出覆盖保证 `P(真值 ∈ 预测集) ≥ 1−δ`。
- **三点区别**：①保证对象（覆盖/召回 vs 误警）；②标签需求（需带标注校准集 vs 零标注杂波位置）；③分布来源（留出真实样本 vs 可生成的零分布，因而样本量可达 10⁴–10⁵，α 可以更小）。
- **v3 追加的第四点（关键）**：conformal 的保证作用于**校准时的那个模型**；本文的保证作用于**部署后的整数模型**——这需要额外的量化误差分析（C1），conformal 没有这一层。
- **诚实**：数学工具（秩统计量/可交换性）同源，主动承认。

## B7. 边缘 / 星上 SAR 处理与昇腾生态

- **GPU 边缘实测**：《基于无损压缩和量化感知的 SAR 舰船检测网络边缘部署》——嵌入式 GPU + TensorRT 混合精度，640×640 达 208 FPS、3.41× 加速、6.2 W。证明"部署实测可发表"，但平台是 Jetson 类。
  - **注意**：它标题里就有"量化感知"，但**只报 FPS 与 mAP**，不报 P_fa。这条是 v3 最重要的"同类但不同问"的引文。
- **FPGA 在轨**：Lightweight CNNs for Embedded SAR Ship Detection（arXiv 2508.10712）——ZCU104 上 Stripmap 原始数据实时检测+分类。
- **昇腾生态**：ultralytics 官方 Ascend 集成（ONNX→ATC→OM）；AMCT 做 PTQ（逐层 scale/zero-point）；ATC `--soc_version=Ascend310B3`。
  - **Atlas 200I DK A2 规格**：8 TOPS INT8 / 4 TFLOPS FP16 / 4 GB LPDDR4X / 4×Taishan V200M @1.0 GHz / ~24 W / 被动散热。
- **本文的空白（两条）**：
  1. **没有一篇测过"量化前后 P_fa 变了多少"**；
  2. **没有一篇测过"误警率 → 候选数 → 后处理尾时延"的耦合**。

# C. 差距分析：四列框架（论文 2.7 节小结表原型）

| 工作线 | ① 优化对象是 mAP 还是**尾分位数** | ② 是否显式建模背景/杂波分布 | ③ 结论是否在**定点整数算术**上成立 | ④ 是否有**板级实测** |
|---|---|---|---|---|
| SAR 检测 SOTA（YOLO/DETR 系） | mAP | ❌ | ❌（从未讨论） | ❌（仅 GPU FPS） |
| PTQ for detection（Inlier-Centric PTQ 等） | mAP | ⚠️（inlier 背景，但仍为 mAP 服务） | ✅（在 INT8 上） | ⚠️（多为 GPU/仿真） |
| Is INT8 Portable? | —（不涉及检测指标） | ❌ | ✅（测量一致性） | ✅（多平台） |
| QAT 家族 | mAP | ❌ | ✅ | ⚠️ |
| 经典 CFAR（CA/OS/GO） | 尾分位数（P_fa） | ✅（像素幅度） | ❌（浮点/DSP，不讨论量化） | ❌ |
| CFARnet | P_fa（软） | ⚠️（软惩罚） | ❌（FP32） | ❌ |
| conformal 检测（SeqCRC） | 覆盖（非误警） | ❌ | ❌（FP32 模型） | ❌ |

| 边缘 SAR 部署（GPU/FPGA/Ascend） | mAP + FPS | ❌ | ⚠️（只跑得动，不讨论契约） | ✅ |
| **本文 QCert** | **尾分位数（P_fa）** | ✅（零标注零模型，且**被量化**） | ✅（按构造成立 + 解析界） | ✅（Atlas 200I DK 实测） |

**读法**：第①列把本文与全部 PTQ/QAT/检测工作分开；第②列把它与 conformal 和普通 PTQ 分开；**第③列是 v3 的新增列，也是"换到 Jetson 上这篇论文就不成立"的那一列**；第④列提供唯一性证据。四列全勾是本文唯一需要的辩护。

## C1. 逐条切割话术（背下来，审稿必问）

1. **"这不就是普通的 PTQ 吗？"** → PTQ 的验收口径是 mAP（Vitis AI 官方门槛就是 mAP 差 ≤1%）。我们证明 mAP 这个口径**看不见**尾部分位数，并给出一个"mAP 几乎不变、P_fa 变数倍"的实例。我们不是做得更好的 PTQ，我们是**换了一个被优化的量**。
2. **"Is INT8 Portable? 已经说了 INT8 不一致，你只是重复。"** → 他们**测量**不一致（958–965/1000）；我们给出（i）不一致如何映射到误警率的**解析界** `|ΔP_fa| ≤ L·δ`，δ 由 scale 表算出；（ii）**整数域判决规则**使契约按构造成立；（iii）**免数据阈值搬运**。从"报告现象"到"给出可控性"。
3. **"这不就是 CFAR 吗？"** → 经典 CFAR 建模像素幅度、浮点、判别力弱；本文建模**深度检测器响应**的零分布，判决量是学生化残差，且阈值在**整数域**由测试场景自身杂波分位数给出。继承契约，丢弃分布假设与浮点假设。
4. **"这不就是 CFARnet 吗？"** → CFARnet 在损失里软惩罚，推理仍固定阈值，FP32，无保证；本文推理期硬标定、整数域、有界、有板级实测。
5. **"这不就是 conformal 吗？"** → 保证对象不同（误警 vs 覆盖）、校准集标签不同（零标注 vs 需标注）、保证作用的模型不同（**部署后的整数模型** vs 校准时的浮点模型）。
6. **"把板子换成 Jetson，你的论文还成立吗？"** → **不成立**（这正是设计目的）。FP16 没有饱和、没有编译期固定 scale 表、没有可读的逐层仿射参数——三条机制中的两条消失，阈值搬运规则无从定义。这个问题我们主动在 Intro 里回答。
7. **"量化误差这么小，你的问题真实存在吗？"** → 我们给量级：σ 的 5% 量化误差在 α=1e-3 处把 P_fa 抬高 1.6×，10% 抬高 2.6×（`Δln P_fa ≈ z²·ε_σ`）。且 E3 用真实 AMCT 配置测 ε_σ 的实测值，而不是假设。
8. **"SSDD 已饱和，还有什么可做？"** → 正因 mAP 饱和、且 mAP 对虚警不敏感，本领域才需要换指标。Fig.1 用实测数据说明这一点。
9. **"保证依赖可交换性吗？"** → 是，且我们主动量化偏差：块抽样 + 报 n 与 n_eff + 相关场实验（E1）。
