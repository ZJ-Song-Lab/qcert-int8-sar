# 创新点技术方案（v3：整数域判决契约）

> 本文档是方法权威来源。结构：问题（1）→ 三个机制（2）→ C1 理论（3）→ C2 系统（4）→ C3 实验（5）→ 切割（6）→ 自检（7）→ 失败模式（8）。

---

## 1. 问题设定

### 1.1 记号

- 输入 SAR 场景 `x`，检测器 `f_θ` 给出逐位置分数场 `s(u) ∈ R`（经 sigmoid）；
- 零模型（零标注训练）给出 `(μ(u), σ(u))`，判决统计量
  `z(u) = (s(u) − μ(u)) / max(σ(u), ε)`；
- 逐场景标定：`λ(x) = Quantile_{1−α}({z(u) : u ∈ Ω_clutter(x)})`，判决 `ŷ(u) = 1{z(u) > λ(x)}`；
- 部署形态：`f_θ` 与零模型被编译为**单一静态图**，激活为**逐层仿射 int8**：
  `a_q = clamp(round(a/Δ_l) + z_l, −128, 127)`，`Δ_l, z_l` 编译期固定且可读。

**全文的争议点**：`λ` 是在 FP32 下算出来的，而推理发生在 int8 上。这两者不是同一个随机变量。

### 1.2 为什么 mAP 看不见这个问题

`mAP` 是对全部检测按分数排序后的积分，**对 99.9% 分位不敏感**；而 `P_fa = α = 1e-3` 恰恰由该分位决定。因此存在一个宽区间：mAP 变化 <1 个点，而 P_fa 变化数倍。**这就是本文要占据的空隙**——现有 PTQ 研究（ICLR 2026 Inlier-Centric PTQ 等）全在优化 mAP。

### 1.3 三条假设（论文必须显式声明）

- **A1**：同一 `.om` 在同一设备上**逐 bit 可复现**（整数 kernel 确定性）；
- **A2**：不同设备/不同量化配置下 **int8 输出不保证一致**（arXiv 2609.16085 已实测）；
- **A3**：量化配置（每层 `Δ_l, z_l`、输出 range）对使用者**可读**（AMCT/ATC 产物）。

在 A1–A3 下，本文主张：**误警率契约可以在整数算术上按构造成立，并在 A2 的情形下被界住。**

## 2. 量化破坏判决的三个机制（逐一给出量级）

### 2.1 分母机制（主导项）

设 `ŝ = s + e_s`、`μ̂ = μ + e_μ`、`σ̂ = σ + e_σ`，一阶展开：

```
ẑ − z ≈ [e_s − e_μ − z·e_σ] / σ
```

若 `|e_s| ≤ Δ_s/2, |e_μ| ≤ Δ_μ/2, |e_σ| ≤ Δ_σ/2`，则相对误差 `ε_z ≈ (Δ_σ/2)/σ`（当 `z` 中等偏大时 σ 项主导）。对高斯尾：

```
ln( P_fa(ẑ) / P_fa(z) ) ≈ (z + 1/z) · Δz ≈ z² · ε_σ
```

**数值**：α=1e-3 → z≈3.09：

| ε_σ | P_fa 倍数 |
|---|---|
| 2% | ×1.21 |
| 5% | ×1.63 |
| 10% | ×2.65 |
| 20% | ×7.0 |

→ **σ 的量化粒度是首要矛盾**，而不是 s 的精度。这条推论给出两个具体设计：σ 用对数域参数化；判决中**消除除法**（第 4 节）。

### 2.2 饱和机制

score head 的输出 range 由校准集统计得到。高杂波场景中强回波使 `s` 撞上 int8 上界：
- 大量位置得到同一个最大整数 → **并列** → 排序信息丢失 → 分位数 λ 被推到上界 → 要么 P_fa 爆炸，要么 P_d 崩塌；
- 该机制在 FP16 上**不存在**，只能在定点图上观测与审计。

**对策**：range 校准集必须按海况分层（三桶各 ≥64 张）；并对 σ 与 s 分别设定 range，避免共用。

### 2.3 逐层舍入累积

`|e_s| ≤ Σ_l (Δ_l/2)·κ_l`，`κ_l` 为到输出的增益。实践中远小于 2.1 的效应，但它是**跨设备不可移植**的根源（A2）：不同 kernel 的累加顺序不同 → 舍入不同 → 尾部次序不同。

## 3. C1：误差界与阈值搬运

### 3.1 命题 2（误警率偏差界）

设 `P_fa(z) = 1 − F_z(z)` 在 `[λ−δ, λ+δ]` 内 Lipschitz 常数为 `L`，则

```
| P_fa(ẑ) − P_fa(z) | ≤ L · δ,   δ = (Δ_s/2 + Δ_μ/2 + λ·Δ_σ/2) / σ
```

**可操作形式**：`L` 用测试场景的经验密度估计，`δ` 完全由 scale 表算出 → **不需要任何新数据**即可预测部署后的 P_fa 偏移量级。

**可证伪预言（P1）**：σ 改为对数域参数化 + 逐通道 scale 后，实测 Δln P_fa 应下降 ≥ 5×。

### 3.2 阈值搬运（免数据跨设备/跨传感器）

在 `s, μ, σ` 三路 scale 分别为 `Δ_s, Δ_μ, Δ_σ` 的整数图中，判决
`(s−μ)/σ > λ` 等价于整数比较 `(s_q − μ_q) · 2^k > λ_int · σ_q`，其中

```
λ_int = round( λ_old · (Δ_σ/Δ_old) · 2^k / (Δ_s/Δ_old_s) )   # 按新旧 scale 比直接换算
```

于是**更换传感器、更换量化配置、更换设备**时，只需读出新 scale 并重算一个整数 `λ_int`，**不需要重跑标定集**。这正是“只有这类板子能做”的能力：GPU 的 scale 不是编译期常量。

### 3.3 整数域标定（首选路径）

更强的做法是**根本不搬运**：把 Ω_clutter 上的分位数直接在整数域算（第 4.2 节），则 λ 与推理同域，契约按构造成立；3.2 的搬运规则用于**无法重跑标定**的场景（跨传感器零数据迁移）。

## 4. C2：整数域判决层

### 4.1 除法消除

```
ŷ(u) = 1{ (s_q(u) − μ_q(u)) · 2^k  >  λ_int · max(σ_q(u), σ_min) }
```

- 全程整数乘加，无除法、无浮点、无 `z` 的量化；
- `2^k` 与 `λ_int` 在编译期固定 → **图可完全静态化**；
- 与 FP32 判决的差异只剩整数乘法的截断，可用 64 位中间量消除。

### 4.2 整数分位数（O(B)，不排序）

1. 在 NPU 上算 `d_q(u) = (s_q − μ_q)·2^k`（或 host 整数代码）；
2. 直方图：`B` 个桶（建议 4096），按 `d_q` 高位索引；
3. 前缀和求第 `k = ⌈(n+1)(1−α)⌉` 个样本所在桶 → 桶内线性插值得 `λ_int`；
4. 桶宽导致的 α 误差 `≤ 1/B`，配插值后实际 `< 1e-4`。

> 关键：**分位数不需要排序**，只需要计数。这让“逐场景标定”在 1 GHz 的 CPU / NPU 上都是 O(n) 单遍，而不是 O(n log n)。

### 4.3 host-free 与 bit-exact

- 决策图与检测图合并为一个 `.om`，host 只做 DMA 与记录；
- 同一 `.om` 重复运行 1000 次，输出逐 bit 一致（A1）；
- 跨设备/跨算子的差异由 A2 承认，并由 3.1 的界覆盖。

### 4.4 与 v2 的关系

v2 的零模型 `(μ, σ)`、`Ω_clutter` 构造、块抽样（8×8 max + 1/64）全部保留——它们提供**被量化的对象**；v3 新增的是“这些量在整数算术上如何保持契约”。

## 5. C3：只有这块板能做的实验（详见 `04`）

| 编号 | 实验 | 不可替代性 |
|---|---|---|
| E1 | 饱和审计：逐层 int8 饱和率 × 海况，关联漏检率 | 定点独有 |

## 6. 与最接近工作的切割（写作时逐条用）

1. **PTQ for detection**：他们优化 mAP；我们优化尾分位数。给出一张“mAP 不变、P_fa 变 5 倍”的图作为存在性证明。
2. **Is INT8 Portable?**：他们测量不一致；我们给出界与修正，把不一致变成可管理的量。
3. **CFARnet**：软约束、FP32、无保证；我们整数域、按构造成立。
4. **conformal 检测**：保证覆盖且需标注校准集；我们保证误警且校准集为零标注杂波，且保证对象是部署后的整数模型。
5. **量化感知训练（QAT）**：需要重训与标注；我们只做 PTQ + 标定，可在板端秒级完成。

## 8. 失败模式与对策

| 失败模式 | 判据 | 对策 |
|---|---|---|
| 量化不改变 P_fa | FP32/INT8 比值 < 1.5 | 转为“饱和审计”主线：构造高杂波压测集，逼出饱和 |
| σ 量化误差被 AMCT 自动规避 | 全 INT8 强制后仍无漂移 | 改叙事为“证明 PTQ 对误警率安全”，仍有价值但需换期刊定位（GRSL） |
| 整数直方图在 NPU 上过慢 | 决策层 > 3 ms | 退到 host 整数代码（仍 bit-exact，仅多一次 DMA） |
| 跨设备对照数据不足 | 只有一块板 | 用 ONNX-Runtime INT8 与 FP32 作三点对照，明确标注平台差异 |
| 审稿质疑“保证依赖交换性” | — | 保留 v2 的块抽样与 n_eff 报告，主动给出偏差量化 |
