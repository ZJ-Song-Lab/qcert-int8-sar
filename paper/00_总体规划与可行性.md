# 总体规划与可行性（v3：整数域判决契约）

> **一句话定位**
> 现有 SAR 舰船检测器把阈值标定在 FP32，却部署在定点 NPU 上——这是一个**静默失效**的范式错误。本文证明误警率由分数分布的尾部分位数决定，而 INT8 定点恰好只破坏尾部；据此给出量化误差到误警率的解析界、保持契约的整数判决规则，并只在 Atlas 200I DK 上完成验证。
>
> **题目候选**
> - `QCert: Making False-Alarm Guarantees Survive Integer Quantization for On-Board SAR Ship Detection`
> - 中文：`整数域误警率契约：星载 SAR 舰船检测的量化一致性`
>
> 文档体系：`00`（定位与决策留档）/ `01`（大纲）/ `02`（技术方案，权威）/ `03`（文献）/ `04`（实验）/ `05`（实施）。

## 1. 为什么必须换到“硬件算术”这条轴上

### 1.1 v1、v2 被否的两个原因（留档）

| 版本 | 主张 | 被否原因 |
|---|---|---|
| v1 EdgeSAR-Net | 难度门控 + 多出口 + 异构感受野 MoE + 免重训剪枝 | 全是模块堆叠；每条都被 2026 年工作占位（SARES-DEIM 占 MoE、BLANKSKIP 占早期退出、AFS-Net/SED-FOD 占跨域） |
| v2 NullSAR | 零假设 + 逐场景分位数 → 有限样本误警率保证 | **数学保证与硬件无关**：同一公式在 GPU 上也成立，Atlas 只是测量台；创新与部署是两张皮 |

### 1.2 v3 的判断

要让硬件成为**创新来源**，方法的正确性必须依赖这块芯片的算术特性。Ascend 310B 提供了三个 GPU 没有的硬事实：

| 硬件事实 | 方法含义 |
|---|---|
| 编译期静态逐层仿射量化（scale/zero-point 固定且**可读**） | 量化误差**可解析**；阈值可**免数据**搬运到新设备/新传感器 |
| 输出张量有固定 int8 值域 | 高杂波场景会**饱和**，排序塌陷——这是 GPU FP16 不存在的失效模式 |
| 图内无高效排序/gather；host 为 4×Taishan @1.0 GHz | 分位数与候选提取必须**离开 host**，且不能依赖排序 |

### 1.3 核心洞察（本文的“钩子”）

1. **P_fa 是尾部分位数，mAP 不是。** α=1e-3 对应分数分布的 99.9% 分位；mAP 是对全排序的积分，对尾部几乎不敏感。
2. **量化误差恰好住在尾部。** 三个机制——输出饱和、分母 σ 的量化粒度、逐层舍入累积——都只改变大分数区域的相对次序与幅值。
3. **分母主导。** 学生化残差 `z=(s−μ)/σ` 中 σ 在分母，故一阶有 `Δln P_fa ≈ z²·ε_σ`（`ε_σ = Δ_σ/2σ`）。α=1e-3（z≈3.09）时，**σ 的 5% 量化误差 → P_fa ×1.6；10% → ×2.6**，而 mAP 几乎不动。
4. **INT8 不可移植是已被实测的事实**（arXiv 2609.16085），所以“FP32 标定、INT8 部署”在原理上就不成立，而不是工程细节。

## 2. 三条贡献

### C1 量化—误警率误差传播与阈值搬运（理论）

- 给出 `|P_fa(INT8) − α|` 的解析上界，输入只需：每层激活 scale、输出 range、零模型的 σ 动态范围；
- 给出**阈值搬运规则**：旧设备/旧传感器的 λ 用 scale 表可直接映射到新设备（跨量化配置、跨传感器），**零校准数据**；
- 可证伪预言：σ 的量化粒度是主导项 → 把 σ 改为对数域参数化 + 逐通道 scale 后，P_fa 漂移应下降一个数量级。

### C2 整数域判决层（系统）

- **除法消除**：`(s−μ)/σ > λ` ⇔ `(s−μ)·2^k > λ_int·σ`，避免对 σ 做除法与对 z 做量化，判决在整数域**精确等价**；
- **整数分位数**：直方图 + 前缀和（O(B)），不用排序，给出桶宽导致的 α 误差界；
- host 完全退出回路 → **单设备 bit-exact、P99 = mean**。

### C3 只有这块板能做的五组实验（证据，编号与 `04` 一致）

| 实验 | 为什么只有在板上做才成立 |
|---|---|
| **E2 饱和审计**：逐层统计 int8 饱和率与并列数，关联漏检/虚警 | 饱和是定点图独有现象；FP16 不存在 |
| **E3 跨精度可移植性**：同一 `.om` 重复运行 vs ONNX-Runtime INT8 vs FP32 的判决差异与 bit-exact 复现 | 需要真实 `.om` 的整数 kernel；FP16 无逐层仿射整数舍入 |
| **E5 阈值搬运**：只凭 scale 表把 λ 搬到新配置/新传感器 | **GPU 的 scale 不是编译期常量，"搬运"在 GPU 上无处定义** |
| **E6 热稳态契约保持**：连续运行至温度稳态，P_fa 与 P99 是否仍守约 | 被动散热 + `npu-smi` 采样只能在板上测；且 A1（整数确定性）使降频只影响时延、不影响 P_fa——这条结论本身就是板级红利 |
| **E7 J/艘**：板级功率 / 检出船数，含热降频 | 同上 |

> 其余实验（E0/E1/E4/E8/E9）在 GPU 上也能跑，但它们不承担"只有这块板"的卖点，只承担命题与对照。

## 3. 与最接近工作的切割

| 工作 | 他们做什么 | 我们不同在哪 |
|---|---|---|
| PTQ for Detection（ICLR 2026 Inlier-Centric PTQ 等） | 优化 **mAP** 的量化误差 | 我们优化 **尾部分位数**；mAP 对尾部不敏感，这是两套目标 |
| Is INT8 Portable?（arXiv 2609.16085） | **测量**跨平台 INT8 不一致 | 我们给出**误警率的解析界 + 修正规则**，把“不一致”变成“可控” |
| CFARnet（2208.02474） | 损失里软约束 CFAR | 我们在推理期、在整数算术上按构造成立 |
| conformal 检测（SeqCRC 等） | 覆盖保证，需带标签校准集 | 我们保证误警率，校准集为零标注杂波；且保证对象是**部署后的整数模型** |
| SAR 边缘部署实测（GPU/TensorRT/FPGA） | 报 FPS 与 mAP | 报 **P_fa 的精度不变性**与尾时延、J/艘 |

**一句话**：别人在“量化后还能不能检测得准”，我们在“量化后还敢不敢承诺虚警率”。

## 4. 硬件与数据可行性

- **板卡**：Atlas 200I DK A2，Ascend 310B，8 TOPS INT8 / 4 TFLOPS FP16，4 GB LPDDR4X，4×Taishan V200M @1.0 GHz，~24 W，被动散热。足以训不了模型但足以跑 n 尺度检测器 + 整数决策层。
- **训练**：单卡云 GPU；模型 <3 M，SSDD 规模小。
- **数据**：SSDD（主）、HRSID（近岸压力）、SAR-Ship-Dataset（留一传感器）。**传感器元数据是 C1 跨设备搬运的必需项**，M0 必须先核查。
- **量化工具**：AMCT（PTQ）+ ATC + ACL；`--soc_version` **以板上 `npu-smi info` 实测为准**（`asc-sar/README.md` 记录 A2 为 `Ascend310B1`，部分批次为 B4，不要照抄 B3）；scale 表须能从 AMCT 配置或 `.om` 元数据读出——这是 C1 的前提（对应 05 的 R2）。

## 5. 诚实边界（必须写进论文）

1. 保证是**边缘/逐场景**的，不是逐像素条件保证；
2. 分位数在**整数域、同域标定**：λ 由部署算术自身的 `z_q` 分位求得，故 `α ≥ 1/n` 仍成立，n 受块抽样后的有效样本数限制，约 1e-3~1e-4（`04` §1.3 中 `Ω_clutter` 与 `Ω` 必须分开报告）；
3. **不承诺 P_d 提升**；主张是“同 P_d 下误警率在定点硬件上不漂移”；
4. 单板验证：跨设备一致性用 CPU/ONNX-Runtime INT8 作对照，不冒充多板实测；
5. 若实测显示 σ 量化误差远小于预期（例如 AMCT 自动给了足够细的 scale），则 C1 的主线要改为“饱和主导”，结论方向不变但叙事需重写——这是 E4（M5）要回答的问题。

## 6. 风险与门槛

> 下表是**决策层**风险；工程级风险 R1–R10（含“scale 表读不出”这一致命项）见 `05` §6。

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | **INT8 下 P_fa 几乎不漂**（量化误差太小） | 致命（论文失去问题） | **M1 硬门（E0）**：若 FP32↔INT8 的 P_fa 比值 `R` < 1.5，改走“饱和审计”主线（E2 压测）或换路线 |
| R2 | AMCT 自动混合精度掩盖了问题 | 高 | 强制全 INT8（禁 fallback）后测；这本身也是论文的一个受控设置 |
| R3 | 整数分位数的桶宽误差过大 | 中 | B=4096 桶 + 桶内线性插值；报 α 误差界 |
| R4 | host-free 后仍然慢（NPU 上做直方图不易） | 中 | 直方图在 NPU 上用 one-hot matmul 近似；退路是 host 整数代码（仍 bit-exact） |
| R5 | 审稿认为“只是工程” | 高 | 用 C1 的解析界 + 可证伪预言（σ 对数域化后漂移降一个数量级）撑住科学性 |
| R6 | 跨传感器无元数据 | 中 | 用 scale 搬运不依赖元数据，只需旧/新设备的量化配置 |

## 8. v1/v2 废弃理由留档（回应用户“不要缝缝补补”）

- v1 的四个模块各自都有 2026 年的占位工作，组合起来也不构成新问题；
- v2 的数学正确但**与硬件解耦**，部署沦为验证章节；
- v3 的唯一新增假设是“算术是定点且 scale 已知”——这个假设**只有在这类板子上才成立**，因此创新与硬件同生共死。
