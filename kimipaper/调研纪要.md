## 一、background 资源可借鉴点

### 1.1 各项目核心创新

| 项目 | 任务 | 核心创新 |
|---|---|---|
| **YOLO-Master-main**（腾讯优图，CVPR 2026） | 实时检测框架 | ES-MoE 动态路由；MoA/MoT（静态图友好的 Transformer 混合）；Sparse SAHI（objectness 引导稀疏切片，大图小目标 3–5× 加速）；CW-NMS（聚类加权 NMS）；LoRA/MoLoRA；完整 ONNX/TRT/ncnn 导出链（Ultralytics 生态，官方支持导出 Ascend OM） |
| **NuWa-main**（HUST） | 类别特定轻量 ViT 推导 | SKP 自知识净化（Top-K 二值化 mask 剪掉 class-detrimental 权重）；OFP 免重训练闭式剪枝（MHA 的 W_QᵀW_K / W_VᵀW_O SVD 能量降维；MLP 删列/闭式补偿 `(2XᵀX+γI)⁻¹`/pinv 最小二乘重建）；head_focus 类别特化；比 SOTA training-free 剪枝最高 +29% 精度、推导提速 33.69× |
| **Fast-FoundationStereo**（NVIDIA，CVPR 2026） | 实时零样本立体匹配 | 三分治加速：教师混合骨干→单学生骨干的**多级特征金字塔 MSE 蒸馏**；cost filtering 块级 NAS + ILP 预算搜索（O(n^N)→O(n)）；ConvGRU refinement 结构化剪枝（递归依赖图 + Taylor 重要性）；**自动伪标签管线**（teacher + 单目深度 3D 一致性 mask + 开放词汇分割过滤 → 1.4M 训练对） |
| **BLANKSKIP**（2603.28149，Politecnico di Torino） | 纳型无人机机载检测（GAP8 RISC-V） | Early-exit 空帧门控：骨干中间层挂极轻 EE 分支做"空/非空"二分类，置信度≥τ 早退；端到端复合损失；τ 显式控制漏检率-算力权衡；8-bit 量化实机 MAC 降 22.5%、吞吐 +24% |
| **EvoComp**（2604.17087，OPPO） | MLLM 视觉 token 压缩 | Encoder-only Compressor 即插即用；进化式标签生成（以任务损失为目标搜二值掩码）；**GHM loss** 处理保留 token 少数类不平衡；cosine 相似度损失 |

### 1.2 迁移到本论文的技术点映射

- **直接可用**：特征蒸馏（FFS）、Sparse SAHI 稀疏切片、CW-NMS、GHM loss、LoRA 小样本适配、Ultralytics→ONNX→ATC 部署链。
- **需改造但价值高**：NuWa OFP 闭式剪枝（ViT→CNN 检测器）；SKP detrimental 权重净化（SAR 本质是 ship/background 少类任务，契合度高）；BLANKSKIP 门控（与稀疏切片二选一）；FFS 伪标签管线（多模型一致性过滤）。
- **仅思路启发**：EvoComp 进化搜索；FFS 块级 NAS（需把 GPU 延迟换成 Atlas 实测）。

### 2.2 技术热点（按可落地性）

1. 轻量 YOLO 变体（AC-YOLO、DS-YOLO 等）——★★★★★ 但单改模块已无新意；
2. 剪枝+蒸馏压缩——★★★★（信号处理 2024：SSDD 参数 −80.3%）；
3. INT8 量化/QAT——★★★★，SAR 小目标敏感性未被系统研究；
4. NMS 外置、AIPP/DVPP 预处理下沉——★★★★ 纯工程但论文少；
5. 海杂波抑制/频域增强——★★★；
6. 跨传感器域泛化——★★★（共同盲区：不考虑量化）；
7. 旋转框（CSL/DCL 规避旋转 NMS）——★★★；
8. VMamba 骨干——★★（selective_scan 在 310B 无支持，难落地）。

### 2.3 Atlas 200I DK（Ascend 310B）要点

- **规格**：8 TOPS INT8 / 4 TFLOPS FP16，无 FP32（需 force_fp16），4GB LPDDR4X，4 核 1.0GHz 弱 CPU。
- **流程**：PyTorch → ONNX（去 NMS）→（AMCT PTQ/QAT/剪枝）→ ATC（soc_version=Ascend310B1/B4）→ ACL 推理 + CPU 后处理。
- **已发表空白**：唯一 SAR 边缘部署论文是 GPU+TensorRT 平台；昇腾侧只有通用视频检测论文。**"SAR + Ascend 310B"组合基本无已发表工作**——本论文的核心空白依据。
- **常见坑（论文卖点素材）**：
  1. NMS/旋转 NMS 无算子 → 导出无 NMS 图 + CPU 后处理；
  2. PTQ 量化域外校准可致 ~25% mAP 损失 → 域内校准 + QAT + 混合精度 skip_layers；
  3. force_fp16 与 PyTorch FP32 数值对齐；
  4. 动态 shape 推断失败 → 固定 640、batch=1；
  5. 4GB 内存限制与多路复用；
  6. 算子白名单（grid_sample、selective_scan 等不支持）。

## 三、结论

- 选题方向（算法—量化—部署协同设计）有明确的领域空白 + 真实平台痛点 + 手头代码资源三重支撑；
